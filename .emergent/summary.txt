    *   This feature has undergone significant architectural changes based on user feedback. The final, approved architecture is as follows:
    *   **Strict Separation of Concerns:**
        *   **Panels = Data Layer:** Panels define a schema (fields) and store records. They do not contain any workflow logic. They can optionally define a list of allowed source panels for validation purposes.
        *   **Rules = Workflow Layer:** Rules define the automation logic.
    *   **Rule Structure:**
        *   A rule is triggered by **one source panel** (e.g., on record creation/update).
        *   A rule can execute actions on **multiple target panels** (both custom and system panels like Inventory).
        *   Each target action is independent and configured separately within the rule.
    *   **Data Integrity:**
        *   The system must enforce a **Single Source of Truth**. When a rule executes, data for all target actions must come directly from the source record, not from intermediate panels.
    *   **Admin Configuration:**
        *   **Field Mapping:** For each target panel in a rule, the admin must explicitly map which source fields populate which target fields.
        *   **Field Visibility:** For each target panel, the admin must define which fields are visible and/or editable in the resulting records.
        *   **UI:** The rule builder UI must be driven entirely by dropdowns, with the only free-text input being the rule name.

**Key Technical Concepts**
-   **Decoupled Architecture:** The system now strictly separates the **Data Layer (Panels)** from the **Workflow Layer (Rules)**. This is the most critical concept to understand.
-   **Single Source of Truth:** The execution engine is designed to always pull data directly from the original source record for all target actions, preventing data corruption.
-   **Multi-Target Actions:** A single rule can trigger independent create/update actions on multiple different panels.
-   **Explicit Configuration:** The system relies on explicit admin configuration (dropdowns for everything, field mapping, visibility controls) rather than implicit or automatic logic.
